## Manual (live)
### Gold rate job (run in WSL from the repo root)
Orders need a gold rate set within the last 24 h; without one every order answers `needs_info` (topic `gold_rate`) and asks for today's rate.
1. `./venv/bin/python run.py rates refresh` — fetches the MCX gold price from the Economic Times page, adds ₹5,000 per 10 g, writes all four karats to `data/gold_rates.json`. Expected: `Rate updated from MCX <x>/10 g (+5000): 24K ₹…/g, 22K …, set <time>.` and exit 0. Sanity: 24K ≈ (MCX + 5,000)/10. On a network or page problem: `Rate not updated: … Last rate kept: …` and exit 1, file unchanged.
2. `./venv/bin/python run.py rates show` — each karat with rate, time, source, and `OK` / `STALE` / `OUT_OF_RANGE` / `FUTURE`.
3. Offline demo: `./venv/bin/python run.py rates set 24=14200 22=13000 18=10650 14=8300` (owner, range-checked; `source: manual`).
4. Worker: `./venv/bin/python run.py rates refresh --every-h 6` (Ctrl+C to stop).
5. Stale check: edit a `set_at` in `data/gold_rates.json` to 2 days ago, run order 1 below — expected `needs_info` naming the old rate and time, asking for today's rate.

## Known gaps
- Gem dispersion is not rendered on bpy 5.0.1 (the wheel exposes no dispersion socket); check diamond renders by eye.
